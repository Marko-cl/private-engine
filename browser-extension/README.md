# Private Context Engine browser connector

This is an optional Manifest V3 source connector for the local Private Context Engine. It is deliberately an untrusted, minimized observation client.

## Current support

The source targets Chromium-style Manifest V3 APIs. It has not been manually packaged or tested in a browser in this development environment. Do not claim Chrome, Edge, or another browser is supported until manual installation and connector testing are completed.

## Installation and pairing

1. Start the desktop application.
2. Load this directory as an unpacked Manifest V3 extension in a Chromium-compatible browser.
3. Open the extension popup and choose **Pair with desktop**.
4. In the desktop application, approve the pending pairing request in the Browser Context section.
5. Enable browser context in the desktop application and in the extension popup.
6. Revoke pairing from the desktop application to invalidate the stored token.

The extension stores only its pairing token and small status values in browser extension storage. It does not create a browser history database.

## Requested permissions

- `tabs`: read the active tab's URL and title so the existing minimized payload can be formed. No page contents are read.
- `storage`: retain the pairing token and enablement state across extension restarts.
- `alarms`: wake the service worker for active-tab bookkeeping.
- `http://127.0.0.1:47631/*`: communicate only with the fixed local connector endpoint.

The extension does not request cookies, history, bookmarks, downloads, webRequest interception, scripting, native messaging, or broad page access.

## Collected data

Only the active tab's domain, URL, title, timestamp, and bounded duration are sent. The desktop main process remains authoritative for URL sanitization, domain rules, privacy pause, payload validation, storage, and source attribution.

The extension never collects or transmits HTML, DOM text, screenshots, form fields, typed text, passwords, tokens, cookies, local/session storage, clipboard data, private messages, email/chat contents, browser history, bookmarks, saved passwords, autofill data, microphone data, camera data, or downloaded file contents.

## Connector protocol

The desktop listens only on `127.0.0.1:47631` and exposes three narrow endpoints:

- `POST /pair-request`
- `GET /pair-status?requestId=...`
- `POST /submit` with `Authorization: Bearer <paired-token>`

The extension cannot invoke Electron IPC or any action capability. Requests are size-bounded, authenticated after pairing, rate-limited to 60 accepted requests per token per minute, and revalidated by the main process.

The token is generated by the desktop, returned only to the extension after explicit desktop approval, stored as a hash by the desktop, and revocable. It is never placed in renderer dashboard state or diagnostics.

## Privacy behavior and limitations

Desktop disablement and privacy pause reject incoming records even if the extension sends them. Browser records are stored only in the Electron `browser_context` table after existing validation. Active-tab duration is transient and best-effort; service-worker suspension or browser shutdown may prevent an exact final duration.
